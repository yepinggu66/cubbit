# v2.2 空闲/睡眠节流 — 测量记录（2026-11-02，Linux + Xvfb + Electron 45.2.1，软件渲染）

方法：全新 userData、跳过引导页，启动 30s 后采样 90s 的进程 CPU ticks（1 tick = 10ms）与 RSS 总和。
睡眠阈值用 `CUBBIT_IDLE_SEC=5 CUBBIT_SLEEP_SEC=10` 缩短以便测到睡眠模式（Xvfb 无输入，即"离开电脑"场景）。

| 版本 | main | renderer | gpu | 合计 | RSS 合计 |
|---|---|---|---|---|---|
| 改前 (57223f5) | 87 | 284 | 948 | 1319 | 699 MB |
| 改后·睡眠模式 | 29 (-67%) | 215 (-24%) | 986 | 1230 (-7%) | 698 MB |
| 改后·默认阈值（仅进入空闲） | 60 (-31%) | 246 (-13%) | 987 | 1293 | 701 MB |

模拟一小时典型使用（tests/couple-rt/power.test.js）：主进程轮询唤醒 158400 → 36086 次（22.8%）。

结论 / 待办：
- 主进程与宠物渲染进程开销明显下降；内存基本不变（节流不减少常驻内存）。
- GPU 进程开销主要来自透明窗口合成（软件 GL），在 Xvfb 下不受影响；需在 Windows 真机（硬件加速）复测，
  如仍偏高可考虑睡眠时降低窗口尺寸或暂停 `backdrop-filter`/阴影类效果。
