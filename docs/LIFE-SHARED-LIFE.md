# 人生账本 v2：把「账本」和「宠物」缝成一个东西

上一版做出的是两个界面：桌面上有一只宠物，面板里有一本账本。用户会很自然地把它理解成"桌宠里塞了个小游戏"。

这一版做四件事，目标是让两个界面变成一件事：

1. 四条资源长到宠物身上（毛色 / 待机动作）
2. 结局卡导出成能发朋友圈的 PNG
3. 同命局：两个人轮流按，共用一条命
4. 跨端接续：手机上想好，电脑上执行

---

## 一、资源 → 它今天的样子

### 做了什么

`lifegame.resourceMood(state)` 把寿命 / 现金 / 精力 / 自由翻译成一个状态：

| level | 触发条件 | 毛色（滤镜） | 待机速度 | 台词 |
|---|---|---|---|---|
| `steady` | 第 6 步以后，四项都不错 | `hue-rotate(4deg) saturate(1.12) brightness(1.04)` 暖橙 | 0.92× | 我今天状态不错，你想做点什么？ |
| `normal` | 默认 | 原样 | 1× | 普通的一天，也挺好。 |
| `tired` | 精力 < 30 | `-6deg / 0.78 / 0.92` 暗一档 | 1.42× | 我有点累了……今天能不能只做一件小事？ |
| `broke` | 现金 < 0 | `32deg / 0.58 / 0.9` 发土黄 | 1.26× | 钱有点紧，我说话都不敢大声。 |
| `caged` | 自由 < 35 | `190deg / 0.45 / 0.93` 冷蓝灰 | 1.32× | 最近好像什么都得听别人的。 |
| `danger` | 寿命 < 8 年 | `0deg / 0.22 / 0.8` 近灰度 | 1.6× | 我们得慢一点了，真的。 |

优先级是刻意的：**命快没了 > 没钱 > 没自由 > 没精力**。越靠前越该被一眼看见。

`mood.reasons` 会同时给出口语化理由（"只剩 6.2 年""现金已经是负的"），面板提示和测试都用它。

### 只改颜色和节奏，不改素材

12 只形象 × 2 帧是按同一套基准对齐的（角色高占 86%、脚底落 96%）。任何几何或尺寸改动都会让它们互相对不上，而**颜色和动画时长是免费的**：

- 颜色：`hue-rotate` + `saturate` + `brightness` 三个滤镜，叠在位图 `<img>` 上
- 节奏：把所有 idle 动画的时长写成 `calc(3.4s * var(--life-tempo, 1))`，一共改了 19 条规则

一处必须记住的坑：**行走动画（`artWalk`）不能跟着变慢**。它和窗口 190px/s 的位移是同频的，慢下来就会滑步。所以 `artWalk` 被排除在 tempo 之外。

### 实现路径

```
lifegame.resourceMood(state)
  → main/ledger.js  emit('mood')
  → main/main.js    sendPetEvent('life-resource', mood)
  → renderer/pet    applyResourceMood()：CSS 变量 + .life-* 类名 + 一句气泡
```

选择"事件推送"而不是"宠物自己算"，是因为**主进程才是账本的唯一权威**（一天一步的判定也在那里）。宠物只负责表现，不参与记账。

启动时会补推一次当前状态。不补的话每次重启毛色都回到默认，用户会以为账本里的进度丢了——**界面和状态对不上是最伤信任的一种 bug**。

## 二、结局卡：四十步才有的一张图

### 和其它分享卡的区别

| | 清单卡 / 单卡 | 结局卡 |
|---|---|---|
| 说的是 | 我挑了这几条 | 我把一辈子过成了这样 |
| 用途 | 转发一条建议 | 自我介绍 |
| 结构 | 标题 + 最多 5 条 | 结局名 + 三格数据 + 最后三步 + 一句总结 |

结局卡是整个玩法里**唯一会被主动发到朋友圈的东西**，所以它是单独一条渲染分支（`drawEndingCard`），不是复用清单卡的排版。

### 三个设计决定

1. **三格数据必须画上去**（活到几岁 / 最后手里多少 / 真正执行几条）。没有这三格，整张图只是一句狠话，没人会信。
2. **最后三步要留着**。结局是结果，"做 · 面部填充避开鼻背… / 做 · 不频繁交易股票"是过程。有过程才像真的一辈子。
3. **纯矢量，不画外部图片**。`file://` 页面把图片画进 canvas 会污染画布，`toDataURL` 直接抛错。这不是审美选择，是硬约束。

实测：导出 1200×630 PNG，**444 KB**，落盘 + 复制到剪贴板。测试不信文件名，直接读 PNG 字节的 IHDR 校验尺寸。

## 三、同命局：两个人，一条命

### 规则

- 四十步，`turn % 2` 决定这一步算谁的
- **共用同一条命**：一份寿命、一个钱包、一份精力、一份自由
- 每一步都记 `log.owner`，结算时能算清"谁按了几步、执行了几条"
- 台词会带上"（小林按的）"——两个人共用的账，责任得看得见

### 两个刻意的取舍

**不做两份资源。** 两份资源只是两个单人局并排跑，"共享一条命"就没有分量了。真正的张力在于：你替对方做的决定，对方也要承担。

**不锁"只能轮到谁按"。** 情侣多数时候挤在同一台电脑前，锁定回合就得换设备，体验直接崩。所以 owner 是标注而不是门禁。

### 边界（必须说清）

当前的同命局是**同机热座**：两个人轮流用同一台电脑。跨设备同步要接情侣服务（`couple-rt:event` 那条通道已经存在），把"谁按了这一步"作为一条事件广播过去。没做完之前不要在宣传里写"两台电脑一起玩"。

### 代码契约

```js
G.create(now, { duo: { names: ['小林', '阿岚'] } })  // 开同命局
G.duoOwnerOf(state)   // 0 / 1 / -1（单人局）
G.duoInfo(state)      // { names, owner, steps:[a,b], acted:[a,b], left }
G.choose(...)         // result.owner，log.owner
```

老存档没有 `duo` 字段时自动兜成单人局，不改动原有数值。

## 四、跨端接续：手机上想，电脑上按

### 只带走"今天这一手"

整局状态里 `used` 有几百个卡 id，塞进 URL 会到几 KB，微信/短信里必断。所以链接里只装：

```json
{ "v":1, "d":"2026-11-08", "t":3, "a":25, "c":43000, "e":100, "f":99, "l":61.8,
  "n":["小林","阿岚"], "k":[[卡id,标题,证据,章节,钱,时间,毅力,正文60字], ...] }
```

base64url 之后**实测 1.36 KB**（三张卡带 60 字摘要）。再长就该压缩了，再短手机上看不到内容。

### 回来的是一个 8 字符的决定码

```
D1.<0|1|2>.<d|s>      // d = 执行，s = 放弃
```

为什么这么短：它只需要回答两个问题——**第几张、做不做**。手机不需要算结算，结算永远发生在主进程。

### 为什么不当场落账

手机上点错一个数字，少的就是几年寿命。所以贴回决定码之后，面板只做**预选 + 提示"手机上说：执行《…》"**，仍然要用户按一下执行。

### 隐私

手机页 `site/life.html` 是纯静态的：解码在浏览器里做，**不上传、不登录、不留存**。测试断言里也覆盖了"垃圾输入不会让面板崩掉"。

顺带修掉两个旧 bug：

1. **照片宠物 id 会短一格**：`hash().toString(16)` 丢前导 0，偶尔只出 6 位。加 `padStart(8,'0')`。
2. **照片页 demo 会沉默失败**：demo 依赖 `img.decode()` 一张 webp，机器一忙就卡住，表现为"没有报错、界面空着"。改成纯 canvas 合成 + 显式 `catch` 打日志。

## 还没做的

1. **同命局跨设备**：现在只有同机热座，跨设备要接情侣服务的实时通道。
2. **毛色接心理状态**：现在毛色只反映账本资源，还没和 `LifeSystem` 的 mood（饿了/想你/困了）叠加。两者叠加需要一个优先级规则，否则会互相打架。
3. **结局卡带二维码**：现在只有文字链接。二维码能让人真的扫进去走一局。
4. **接续码自动同步**：理想状态是手机选完，电脑自动收到；现在要人工贴码。要自动就需要一个极小的中继（或者复用情侣通道）。
