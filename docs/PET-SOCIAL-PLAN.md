# 拍一只 · 相亲角 · 健康检索分享

> v3.3 交付说明。三件事一起做，因为它们拼的是同一个东西：
> **桌宠不能只是"可爱的图"，它得有别人没有的东西——你拍的那只、你走的那一辈、它自己的关系。**
>
> 对应三份能力：`pet:photo:*`、`mate:*`、`share:*`。

---

## 一、拍一只：照片 → 桌宠（本机完成）

### 为什么不做"AI 生成新形象"

调用图片模型生成一只"新"宠物，会丢掉照片里最重要的东西——**那真的是你遇见的那只**。
所以这条链路做的是"把它搬进桌面"，不是"照着它再画一只"：

```
选图 / 拍照 → 方形取景（拖动 + 缩放）→ 主进程 nativeImage 解码·裁切·缩放到 512
          → 抠底 → 羽化 → 归一化构图 → 调色 → 补边缘光 → 生成闭眼帧 → 落盘 PNG
```

### 三个关键决定

**1. 归一化必须和内置形象同一套比例。**
角色高度占画布 86%、脚底落在 96%、水平居中。不这么做，换形象那一刻会突然变大变小，一眼假。
`petphoto.normalize()` 是唯一入口，单测断言 `|height/512 − 0.86| < 0.04`。

**2. 抠图只处理"紧贴背景的那一圈"深色像素。**
第一版把 luma < 46 的像素全判透明，结果**眼睛被抹掉了**（深色瞳孔正好命中）。
现在只在 1px 邻域内碰到背景的像素上做这个判断——既去掉毛发缝隙漏出的黑边，又保住五官。

**3. 找不到眼睛就不做闭眼帧，并如实告知。**
`detectEyes()` 只认"上半身、成对、尺寸接近、左右分开"的深色连通块；
找不到返回 `null`，UI 显示"这次没做闭眼帧，不影响使用"。
宁可少一帧，也不要给鼻子画一条眼皮。

### 隐私

- 解码、抠图、编码全在本机；**照片本身不落盘、不上传**，落盘的只有 512×512 成品。
- 成品存 `userData/pets/<id>-{idle,blink}-01.png`，注册表 `pets/index.json`。
- 渲染层拿到的只有 `file://` 地址，不含原图。

### 已知取舍

- 输出 PNG 而不是 WebP：`nativeImage` 只能导 PNG/JPEG，而这里必须要 alpha。单帧 150–300 KB，只在用户主动拍照时产生。
- 纯色背景 + 单一主体效果最好；背景杂乱时会提示"换一张背景更干净的照片"。

## 二、相亲角：写需求 → 匹配 → 双方点头 → 恋爱

### 状态机（每一格都可测）

```
single ──写需求──▶ seeking ──挑一只──▶ proposed ──对方回应──▶ (accept / conditional / hesitate / decline)
                                    └── 你也点头 ──▶ dating ──分开──▶ single
```

**唯一写死的规则：只靠一边点头不算。**
对方给了 `accept` 或 `conditional`（且你答应了那个条件），你还要再点一次"我也愿意"，
才进入 `dating`。这在 `mate.confirm()` 里用 `NEED_PACT` / `DECLINED` / `HESITATE` 三个错误码顶住。

### 契合度怎么算

五个维度：黏人度 / 节奏 / 过日子 / 计划性 / 好奇心。

- 用户拖三条滑杆定基调，**文字里的关键词做加权**：写了"安静"的人，是真的在意安静（权重 +0.55，期望值 ±20）。
- 契合度 = 各维 `1 − |差值|/100` 的加权平均，映射到 **30–97**。不设 100 分——相亲不是抽奖。
- **每张卡必须同时给出"像的地方"和"差得远的地方"**。只夸不挑的匹配，用户第一次见面就知道是假的。

### 对方怎么回

| 分数 | 反应 | 出口 |
|---|---|---|
| ≥ 80 | 直接答应 | 你确认 → 在一起 |
| 62–79 | 答应，但提一个条件（先走满 7 天账本 / 连说三天晚安…） | 答应条件 → 在一起 |
| 46–61 | 犹豫 | 可以**再争取一次**（只一次，第二次会被挡住） |
| < 46 | 婉拒 | 只能换一批 |

### 候选从哪来

- 默认：本地缘分池，种子 = `deviceId + 当天日期`，离线也能走完整流程。
- 配了 `mateEndpoint` 就走网络：
  `POST {endpoint}/match` `{ desire, exclude }` → `{ candidates: [{ id, name, species, traits, bio, steps }] }`。
  失败静默回落本地——对方服务器挂了不能把功能锁死。

### 状态存在哪

`userData/mate.json`，主进程是唯一裁判；渲染层刷新页面不会重抽候选，也不会刷掉对方的答复。

## 三、健康检索 + 分享到站点

### 检索

767 条卡一天只发 3 张，四十年也读不完。想找"体检要注意什么"的人不该靠运气抽卡。

- 默认范围「健康相关」= 8 个章节 208 条（不要早死 / 不要慢慢死 / 紧急情况 / 慢性病 / 家里有老人 / 看病 / 别为了外形把身体搞坏 / 常备药）。
- **一开始打字就自动扩到全部章节**：想找"体检"的人，不该因为那条卡归在"不要慢慢死"里就搜不到。
- 支持章节、证据等级（A/B）筛选；勾选若干条可合成"清单卡"分享。

### 分享

分享卡是 canvas 现场画的 **1200×630** 图（纯矢量，不画外部图片——`file://` 页面把图片画进 canvas 会污染画布，`toDataURL` 直接抛错）。

分享链接里带着内容本身：

```
https://cubbit.app/share.html#d=<base64url(紧凑 JSON)>
```

`site/share.html` 在浏览器里解这个 hash 并渲染成一张可读的卡。**不需要服务器、不需要登录**，
分享出去的链接不是"服务器上的一份副本"，而是"内容本身"。

四个平台 + 本地动作：

| 动作 | 实现 |
|---|---|
| 分享到 X | `https://x.com/intent/post?text=…&url=…` |
| 分享到 Facebook | `https://www.facebook.com/sharer/sharer.php?u=…&quote=…` |
| 分享到微博 / Telegram | 官方 intent |
| 复制链接 / 复制文案 | 主进程 clipboard |
| 存成图片 | 主进程写 PNG 到 `userData/exports/`，同时进剪贴板 |

### 安全边界

- 文案按人眼长度裁剪（CJK 计 1、英文计 0.5，预算 118），避免 X 的 280 权重超限。
- 外链走白名单：`x.com / twitter.com / facebook.com / service.weibo.com / t.me / cubbit.app / pingguye.cn`；
  `http:`、`javascript:`、任意第三方域名一律 `URL_NOT_ALLOWED`。
- 落地页只读 hash，不写入任何存储，不带任何身份信息。

## 五、还没做（按优先级）

1. **相亲角接真实服务**：目前 `mateEndpoint` 是契约，没部署。真实用户池需要 uid、跨用户可见性、举报与拉黑——这三件不做就上线会有安全问题。
2. **照片宠物的"闭眼"更像**：现在画的是弯月形眼皮；如果接入抠图分割模型（把人像抠图那类模型换到动物），边缘质量会明显更好。
3. **分享回流**：落地页现在只能"我也去走一局"；接一个下载引导 + UTM 才能知道分享有没有带人回来。
4. **结局卡导出**：四十步的结局是最有传播力的一张图，现在只做了单卡与清单。
