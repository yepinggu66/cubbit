## 一、为什么是「itch/官网直发 + 2 周」而不是直接上 Steam

| 方案 | 首评风险 | 真实双人数据 | 成本 |
|---|---|---|---|
| 直接 Steam 正式发售 | 高（配对未验证） | 0 | $100 + 2 周审核 |
| Steam 抢先体验 | 中（EA 也开分） | 0 | $100 + 2 周 |
| **本方案：先直发 2 周** | **无**（没有评价系统） | **10 对** | **≈0** |

Steam 的开分是不可逆资产；这 2 周就是把它买下来。

## 三、这版（2.5.1-soft）改了什么

| 改动 | 位置 | 为什么 |
|---|---|---|
| 邀请二维码（`cubbit://pair?code=`，只读展示，扫码不消耗邀请码） | `src/renderer/couple/couple-rt.js` + `pair-qr.js` + `vendor/qrcode.js` | 你要求的配对入口；同时也是演示素材 |
| **「复制邀请信息」**：一条消息含下载地址 + 3 步 + 邀请码 | 同上 | 这才是真正降低配对摩擦的东西：对方收到就能照做 |
| 「复制邀请链接」→ `https://pingguye.cn/cubbit/join?code=` | `src/renderer/couple/*`、`shared/lite-config.js` | 落地页有下载按钮和一键唤起，比裸邀请码好用 |
| **匿名设备可直接配对**（不用先过邮箱验证） | `src/main/couple/service.js`（`SOFT_LAUNCH_ANON_PAIRING`） | 否则 20 个人要先收 20 封验证码邮件，SMTP/垃圾邮件会把「配对成功率」污染掉 |
| 首启加「先自己玩，稍后配对」+ 试用开启失败不再卡住 | `src/renderer/onboarding/*` | 原来的「开始 30 天体验」在服务端不可达时会把用户卡在第 2 步 |
| 托盘/右键去掉「解锁情侣包」（点进去是未开通的死路） | `src/main/tray.js`、`src/main/main.js` | 免费内测不能出现购买入口 |
| 状态显示改「内测版」，不再叫「体验版」 | `src/renderer/ui/ui.js` | 降低「是不是要收费/到期」的焦虑 |
| **托盘「📤 导出内测数据」**：一键复制到桌面并打开文件夹 | `src/main/main.js`、`src/main/tray.js` | 让 40 个人交数据，不能让他们去找 `%APPDATA%` |
| 埋点日期改本地时区 | `src/main/beta-stats.js` | 原实现按 UTC，早上 7 点的事件会落到前一天，直接算错 Shared Day |

**服务端同步做了**：匿名配对开关、安装包静态下载、落地页下载按钮、5 分钟健康看门狗、每日备份。明细见 `交付清单_2026-11-04.md`。

**没改**：定价、i18n、AI、农场、支付、许可服务端。这两周不要碰。

## 五、怎么发、怎么收

### 发给一对情侣
1. 对方在客户端点「生成邀请码」→「复制邀请信息」（自动带上下载链接 + 邀请码 + 3 步），直接转发。
2. 也可以只发一条链接：`https://pingguye.cn/cubbit/join?code=<6位码>` —— 页面里有「下载方块仔」和「打开方块仔并配对」。
3. 安装包地址（微信可直接发文件，也可以发链接）：
   `https://pingguye.cn/cubbit/dl/Cubbit-Setup-2.5.1-soft.exe`
4. 要求：**两个人都装完、都打开过一次**，再算「已激活」。

### 发给单人
只发安装包 + 一句「不用配对，右键它有全部玩法，用两天告诉我还在不在用」。

### 收数据（D14）
- 客户端：托盘右键 → **📤 导出内测数据** → 桌面出现 `Cubbit-内测数据-YYYYMMDD-xxxxxx.jsonl` → 让对方发回。
- 汇总：把文件都丢进 `softlaunch/inbox/`，运行：
  ```
  cd "E:\Deep seek-001\cubbit-assessment\softlaunch"
  node tools/metrics.js --in ./inbox --out ./out
  ```
- 问卷：`反馈表单.md` 直接贴到腾讯问卷/金数据（10 题，3 分钟）。

## 七、这两周明确不做的事

| 不做 | 原因 |
|---|---|
| 不上 Steam、不交 $100 | 先拿数据，别先买票 |
| 不接支付/Paddle | 测试期没有收入，接了只会引入退款和客服 |
| 不做英文界面 | 情侣面板和设置页仍是中文；英文用户进来就是差评素材。**英文版是下一阶段的第一件事**（约 1–2 人日） |
| 不加新功能 | 每加一个都要重新测一遍配对 |
| 不改定价 | 定价等问卷结果 |
| 不做代码签名 | 直发才需要；内测让用户点「仍要运行」即可（`内测须知` 里已写） |

## 八、已知风险与预案

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 服务器挂（单台 2C2G，无监控） | 群里同时说「配不上」 | 立即看 `https://pingguye.cn/cubbit/api/health`；挂了先重启 Node 进程，再考虑加监控 |
| 配对 5xx（服务端 publish 未包 try/catch） | 配对后对方名字显示「TA」 | 客户端已重试一次；让对方发一条消息即可回填 `partnerUid` |

| 招募不足 10 对 | D-1 只有 5 对 | 降级为 5 对 + 50 单人；配对成功率仍可估，Shared Day 置信度下降，报告里标注 |
